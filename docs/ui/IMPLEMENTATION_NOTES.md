# UI 에셋 팩 적용 기록

출처: `C:/Users/Master/Downloads/# Operation_ Dust Zero UI Redesign (1)/assets` (110파일).
프로젝트 사본: `DustZeroUnity/Assets/DustZero/Art/UI_DZ/`, 보존 사본: `design/redesign-2026-10-16/assets/`.

## 적용한 것

- `UiAssetImporter` (AssetPostprocessor): 팩의 `manifest.json` 을 읽어 Sprite(Single),
  PPU 100, Full Rect, Mip 끔, **9-slice border 자동 적용**.
  manifest 는 CSS 순서 `[left, right, top, bottom]`, Unity 는 `(left, bottom, right, top)` 이라
  변환해서 넣는다. 메뉴 `DustZero > Reimport UI Art` 로 전체 재적용.
- `UiArt`: 경로 대신 이름으로 찾는 로더. 파일명을 바꾸면 컴파일 오류로 드러난다.
- `UiButton`: 팩이 면+아래 띠를 **한 장에** 구워 두었으므로, 별도 띠 Image 를 없애고
  `btn_*` / `btn_*_pressed` 스프라이트를 교체하는 방식으로 바꿨다. 눌림 시 내용이 8px 내려간다.
- `UiKit`: 패널=`panel_r40_shadow`, 칩/배지/재화=`pill`, 진행바=`bar_r12`,
  알림점=`badge_dot`, 잠금=`ic_lock`. 코드로 그리던 9-slice 생성기는 제거.
- 아이콘 13종을 팩의 Material Symbols 로 교체하고 `IconPainter.cs` 는 삭제.
- 방 배경을 `backgrounds_temp/bg_room_living.png` 로 교체. 캐릭터가 걸어다니는 바닥은
  그림 속 러그 위치를 비율로 잡았다(0.10~0.90 x, 0.20~0.44 y). 그림을 바꾸면 이 숫자만 조정한다.
- 이름표를 어두운 알약 + 흰 글자로(시안과 동일).

## 적용하지 않은 것과 이유

- **`characters_temp/`, `enemies_temp/` 는 쓰지 않았다.** 팩의 캐릭터는 "로봇청소기 TEMP"
  같은 글자가 박힌 자리표시 원이다. 현재 프로젝트는 원본 웹게임의 `drawChibi()` 를 실행해
  추출한 **실제 원본 아트**를 쓰고 있어, 자리표시로 바꾸면 오히려 후퇴한다.
  실제 SD 아트가 오면 그때 교체한다.
- `DZColors.cs` 를 새로 만들지 않았다. 같은 값이 이미 `UiTheme` 에 있고,
  프로젝트 규칙이 "역할이 같은 매니저를 중복 생성하지 말 것" 이다.
- `SafeAreaRoot.cs` 도 만들지 않았다. 기존 `SafeAreaFitter` 가 같은 일을 한다.
- 에셋 경로는 팩 지시문의 `Assets/Art/UI_DZ` 대신 `Assets/DustZero/Art/UI_DZ` 를 썼다.
  CLAUDE.md 가 게임 자산을 `DustZero/` 아래로 규정한다.
- SpriteAtlas 4종은 아직 만들지 않았다(드로콜 최적화는 출시 전 단계).

## battle/ 적용 (2차)

- **전장 타일을 시안의 의미 기반 세트로 교체.** 원본의 바닥 질감(원목 결·주방 체커·
  욕실 격자·벽 해칭)을 버리고 `tile_path / tile_buildable / tile_blocked / tile_spawn /
  tile_goal` 5종으로 바꿨다. 칸이 "무엇으로 만들어졌는지"가 아니라 "무엇을 하는 칸인지"를
  말하게 하는 시안의 의도다. 바닥별 변형이 사라져 BoardView 의 타일 필드가 13개 → 7개가 됐다.
  **가스레인지·물웅덩이는 팩에 없어** 원본에서 옮긴 자체 타일을 오버레이로 유지한다.
- 배치 강조를 `tile_hl_valid` / `tile_hl_invalid` 로, 사거리를 `range_ring`,
  선택 표시를 `select_ring`, 과열을 `overheat_ring` 으로 교체.
- 덱 카드를 `card_normal / card_selected / card_lowpower / card_locked` 프레임 교체 방식으로
  바꾸고, 재배치 대기는 `card_cooldown_overlay` 를 세로 Filled 로 깎는다(manifest 주석대로).

### 월드 공간 PPU

팩은 PPU 100 이지만 보드 아트는 **한 장 = 한 칸**이어야 Tilemap 의 1유닛 셀과 링 스케일이
맞는다. 임포터가 `battle/tile_*` 은 144, `select_ring`·`overheat_ring` 은 192,
`range_ring` 은 512 로 예외 처리한다. UI 아트는 팩 그대로 100 이다.

## Canvas Scaler Match 를 0 으로 변경

가이드가 "Match 0.5 (검증 필요: 긴 화면에서 0.6–1.0 비교)" 로 열어 둔 항목을 확정했다.

| 기기 | Match 0.5 캔버스 | Match 0 캔버스 |
|---|---|---|
| 1080×1920 | 1080 × 1920 | 1080 × 1920 |
| 1170×2532 | **979** × 2118 | 1080 × 2337 |
| 720×1600 | **966** × 2147 | 1080 × 2400 |
| 1440×3200 | **966** × 2147 | 1080 × 2400 |

Match 0.5 에서는 실제 세로 긴 기기의 캔버스 폭이 1080 이 아니라 **약 970** 이 된다.
모든 배치를 1080 기준 절대 픽셀로 썼으므로 약 10% 씩 넘쳐 화면이 좁아 보인다.
Match 0(가로 기준)이면 캔버스 폭이 어느 기기에서나 정확히 1080 이고, 남는 세로는
방과 전장이 가져간다 — 가이드가 긴 화면에 요구한 동작이다.
`CanvasScalerTests` 가 네 기기에서 폭 1080 을 검사한다.

## 브리핑 화면 (시안 1c 1단계)

제목·웨이브/먼지 수·설명·별 조건 칩·등장 적 목록 + [편성 변경] [작전 시작].
전장에는 `tile_hl_brief` 로 **세 입구의 실제 경로**를 그린다(테이블 경로 세그먼트에서 도출).
브리핑 동안에는 HUD 와 트레이를 모두 내리고, 카메라가 브리핑 패널과 액션 띠 사이에
보드를 맞춘다.

**별 조건은 시안을 따르지 않았다.** 시안 칩은 `클리어 / 청결도 70%↑ / 과열 0회 (추측)`
이지만, 실제 규칙은 `config.starLifeMin = [1, 6, 10]` 이고 `lifeMax = 10` 이다.
즉 청결도 1 이상 / 6 이상 / 10 이상이며 과열은 별과 무관하다.
칩은 테이블에서 생성하므로 수치가 바뀌면 따라간다.

### 전장 아트가 1.44배로 들어갔던 문제

`battle/tile_*` 은 144px 인데 팩 기본 PPU 100 으로 임포트되어 한 장이 1.44칸이었다.
타일이 서로 겹치고 경로 표시가 뭉개진 원인이다. 임포터에 월드 공간 PPU 예외를 넣은 뒤
**재임포트를 해야** 반영된다(`DustZero > Reimport UI Art`). 규칙만 고치고 재임포트를
빠뜨리면 증상이 그대로 남는다.

## 하단 탭이 위로 튀어나왔던 문제

증상: 하단 메뉴를 누르면 아이콘·글자 줄 전체가 바 위로 올라왔다.
원인은 `UiKit.NavItem` 과 `RailCard` 가 **자기 자신의 RectTransform** 을 UiButton 의
`content`(눌림 연출로 8px 내리는 대상)로 넘긴 것이다. 두 위젯은 레이아웃 그룹의 자식이라
위치를 레이아웃이 소유하는데, `UiButton.Repaint` 가 `anchoredPosition.y = 0` 을 직접 써서
레이아웃 결과를 지웠다. 측정값: 탭 줄 `y[94..271]`, 탭 항목 `y[183..360]` — 정확히 89px.

고친 방식 두 가지.
1. 두 위젯 모두 안쪽에 `Content` 자식을 두고 그것을 눌림 대상으로 넘긴다.
2. `UiButton` 이 쉬는 위치를 0 으로 **가정하지 않고** 처음 한 번 읽어 기억한다.

`PlayModeSmoke.AssertNavItemsSitInTheirStrip` 이 탭 항목이 바 밖으로 나가면 실패한다.
홈·스테이지 양쪽에서 검사한다.

## 스테이지 탭 (시안 2a)

구성: 상단 제목 + 재화 → `스테이지 | 콘텐츠` 분절 탭 → 챕터 알약 → 챕터 카드 → 목록.
알약은 세 가지 상태를 가진다(진행 중 = 짙은 단색, 그 외 = 흰 알약, 미해금 = 자물쇠).
UiButton 은 팩이 구워 둔 면만 그릴 수 있어 짙은 단색을 표현하지 못하므로,
색을 데이터로 들고 있는 `UiToggleChip` 을 따로 두었다. 분절 탭도 같은 위젯에
다른 팔레트를 넣은 것이다.

행은 상태별로 다르게 그린다 — 클리어한 행은 별, 지금 도전할 한 행은 커지면서 [도전]
버튼을 달고, 잠긴 행은 자물쇠만 둔다. 높이는 `StageRow` 가 LayoutElement 로 바꾼다.
상단 제목·프로필·사이드 레일은 탭에 따라 바뀐다. 홈만 프로필 알약과 레일을 쓰고,
나머지 탭은 같은 자리에 화면 이름을 넣는다(시안 2a~2f 가 그렇게 그린다).

### 시안을 따르지 않은 곳

- **스테이지 개별 이름이 없다.** 시안은 `거실 입구 / 소파 아래 / 거실 평가` 처럼
  행마다 다른 이름을 보여주지만, 10.15-h `stage.json` 에는 이름 열이 없다
  (`id, order, chapter, no, mapId, ...`). 이름은 `map.json` 의 `nameKey` 하나뿐이라
  한 챕터의 모든 행이 같은 방 이름을 쓴다. 원본도 번호 + 방 이름으로 부른다.
  지어내지 않고 데이터대로 두었다.
- **챕터 보상 버튼을 넣지 않았다.** 시안의 `★5 보상 받기` 에 해당하는 챕터 별 보상
  테이블이 신규 빌드에 없다. 죽은 버튼을 두는 대신 별 진행 막대까지만 그렸다.
- **챕터 썸네일은 빈 면이다.** 챕터 아트가 자산에도 테이블에도 없다.
- **콘텐츠 분절 탭은 안내문만 있다.** 대청소 화면이 아직 없다.

세이브를 **v3 → v4** 로 올렸다. 마이그레이션은 `SaveMigrator` 에 있고 기존 파일은
빈 컨테이너로 시작하되, 출석은 기존 `daily` 값을 받아 하루에 두 번 받히지 않게 한다.

- `SaveData.pass` / `shop` / `att` — 원본 10.15-h 의 `S.pass` `S.shop` `S.att` 와 같은 모양.
- `PlayerProfile.Pass.cs` — 시즌 계산, 레벨, 두 트랙 수령. 원본 `passSeason/passSt/passLv/passClaim` 이식.
- `PlayerProfile.Shop.cs` — 일일/주간/계정 한정, 쿨다운, 지급. 원본 `shopSt/prodUsed/deliver` 이식.
- `PlayerProfile.Units.cs` — 조각 영입과 돌파. 원본 `recruitNeed/canStar/starUp/recruit` 이식.
- 출석은 `attendance` 테이블의 7칸 수레바퀴를 돈다(기존에는 고정 보상 1종이었다).

조용히 집계해 데미지 숫자가 초당 60번 뜨지 않게 했다. 과잉 피해는 빼고 센다.

### 시안을 따르지 않은 곳

- **소환 배너 칩을 숨겼다.** 시안은 `가을 픽업 / 상시 소환 / 우정(추측)` 세 칩을 그리지만
  10.15-h `gacha.json` 에는 풀이 **하나**뿐이고, 두 행의 이름은 `1회 소환` `10회 소환`,
  즉 배너 이름이 아니라 **버튼 이름**이다. 버튼 이름을 배너로 내거는 대신 풀이 둘 이상일
  때만 칩 줄이 나오게 했다.
- **천장 숫자가 없다.** 시안의 `SSR 확정까지 34회 · 66/100` 에 해당하는 누적 카운터가
  데이터에도 원본 코드에도 없다. 대신 테이블이 실제로 정의한 `10회 확정` 을 적는다.
- **확률 정보는 풀 가중치에서 계산한다.** 고지 문구를 따로 적어 두면 동작과 어긋날 수 있다.
- **이야기 탭은 가전 대사를 보여 준다.** 프로필 설정 글은 테이블에 없다.
- **현금·광고는 원본과 같은 테스트 공급자다.** 스토어나 광고 SDK 를 부르지 않는다.
  패스 구매도 상점의 `pass:season` 상품을 거치는 같은 테스트 경로다.
- **결과 화면의 첫 클리어 금테**는 보상 묶음 전체에 붙인다. 원본은 첫 클리어 보상을
  따로 떼어 주지 않고 한 번에 지급하기 때문이다.

### 시안 좌표를 그대로 베끼면 안 되는 이유

시안은 390x844pt 기기에 그려져 있는데 이 캔버스는 390x693pt 다. 가전 상세의 시트를
시안대로 `top:452` 에 두었더니 시트 높이가 음수가 되어 능력치 4칸이 통째로 사라졌다.
세로 분할은 비율(`SheetShare`)로 두고, 각 반 안에서 상대 배치한다.

## 미확인

- 캔버스 폭은 네 기기에 대해 **계산으로** 검증했다(CanvasScalerTests).
  실제 그 해상도로 **렌더해 본 것은 아니다.** 테스트 중 `Screen.SetResolution` 은
  테스트 러너를 불안정하게 만들어 되돌렸다. Device Simulator 확인이 남아 있다.
- `collection/` 등급 프레임은 아직 쓰이지 않는다 — 가전/소환 화면이 미구현이라 쓸 곳이 없다.
- 스테이지 목록은 1챕터 기준으로만 눈으로 확인했다. 2·3챕터는 해금 전이라
  알약 잠금 상태까지만 보았고 목록 내용은 확인하지 못했다.
- 상점 **구매**, 소환 **뽑기**, 패스 **수령**, 가전 **강화/돌파** 는 화면과 메타 함수를
  넣고 컴파일·배선까지 확인했지만, 실제로 눌러서 재화가 깎이고 보상이 들어오는 것을
  끝까지 본 것은 아니다. 자동 검사는 화면이 열리고 글자가 그려지는 데까지다.
- 세이브 v4 마이그레이션은 코드로만 확인했다. 기존 v3 파일을 올려서 열어 본 기록은 없다.
- `collection/frame_n` 과 `grade_n` 은 쓰지 않는다. 이 게임의 등급은 R/SR/SSR 뿐이다.
