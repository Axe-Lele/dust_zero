# 캐릭터 · 상품 · 이미지 추가하기

캐릭터, 대사, 이미지, 스탯, 스킬 수치는 전부 `GameData/tables/*.xlsx` 에 있다.
C# 을 고치지 않고 엑셀만으로 추가할 수 있다. 예외는 **새로운 종류의 스킬 동작** 하나뿐이고,
그 이유는 아래 "코드가 필요한 경우" 에 적어 두었다.

## 두 가지 방법

**1. 도구** — 빈칸을 채우면 관련 테이블에 한꺼번에 써 준다.

`tools/DustZeroStudio.exe` 를 더블클릭한다. 파이썬이 없어도 된다.
파이썬이 있으면 `python tools/dz_studio.py` 로 똑같이 열 수 있다.

> **exe 는 프로젝트 폴더 안에 두어야 한다.** 실행된 자리에서 위로 올라가며
> `GameData/tools/xlsx_io.py` 를 찾아 **디스크의 진짜 변환기**를 불러오기 때문이다
> (번들 사본을 쓰면 임시 폴더를 고치게 되어 아무 일도 일어나지 않는다).
> 밖으로 옮기면 못 찾았다고 알리고 멈춘다.

도구를 고친 뒤에는 exe 를 다시 만든다:

```bash
python tools/build_studio.py
```

빌드가 끝나면 스스로 점검해 볼 수 있다 — 창을 띄우지 않고 결과만 파일로 남긴다:

```bash
tools/DustZeroStudio.exe --selftest check.txt
```

`RESULT=PASS` 가 아니면 묶는 과정에서 무언가 빠진 것이다. 창이 뜨는 것만으로는
openpyxl 이 빠졌는지, 프로젝트를 못 찾는지 알 수 없어서 이 점검을 둔다.
exe 와 `tools/_build/` 는 git 에 넣지 않는다 (42MB, 언제든 다시 만든다).

**2. 엑셀 직접 편집** — 도구와 똑같은 파일을 쓴다. 고친 뒤:

```bash
python GameData/tools/sync_to_unity.py
```

도구는 지름길일 뿐 다른 경로가 아니다. 어느 쪽으로 해도 결과는 같다.

## 캐릭터 하나가 걸쳐 있는 곳

| 테이블 | 파일 | 무엇 |
| --- | --- | --- |
| `unit` | 02_Unit.xlsx | 등급·계열·배치·공격력·사거리·저지·스킬 충전 |
| `skill_param` | 02_Unit.xlsx | 그 가전 스킬의 세부 수치 |
| `string_ko` | 01_Config.xlsx | 이름·짧은 이름·역할·스킬명·설명·**대사** |
| `unit_art` | 11_Character.xlsx | **치비/일러스트 파일명, 로비 걷기 속도** |
| `unit_behaviour` | 11_Character.xlsx | **어느 스킬 동작을 쓰는가** |
| `item` | 05_Reward.xlsx | 조각 아이템(영입·돌파에 필요) |
| `gacha_pool` | 06_Gacha.xlsx | 소환 등장 여부와 가중치 |
| `unit_profile` | 02_Unit.xlsx | 일러스트 정보창의 프로필 문구 |
| `unit_levelup` · `unit_star` · `unit_boost` | 02_Unit.xlsx | 전체 공통이라 보통 손대지 않는다 |

`dz_studio.py` 의 **캐릭터** 탭은 위에서 굵게 칠한 것을 포함해 앞의 일곱 개를 한 번에 쓴다.

## 이미지

`unit_art` 의 각 칸은 **파일 이름(확장자 없이)** 이다. 경로는 코드가 붙인다.

| 칸 | 찾는 곳 | 쓰이는 화면 |
| --- | --- | --- |
| `chibi` | `Art/Sprites/<이름>.png` | 전투, 대청소, 로비 방, 카드 |
| `full` | `Art/Illust/<이름>.png` | 일러스트 정보창 — 전신 |
| `turn` | 〃 | 삼면도 |
| `keys` | 〃 | 설정화 |
| `face1~3` | 〃 | 표정 |

기본 규약은 `unit_<id>` 와 `<id>_full` 식이지만 **규약일 뿐 강제가 아니다**.
두 가전이 같은 그림을 쓰게 하고 싶으면 두 행에 같은 이름을 적으면 된다.

`dz_studio.py` 의 **이미지 세트** 탭이 파일을 규약 이름으로 복사하고 칸을 맞춰 준다.
넣은 뒤 Unity 에서 `DustZero > Rebuild Project Assets` 를 한 번 실행한다.

일러스트가 비어 있어도 게임은 돌아간다. 빌드할 때 경고만 뜬다 — 작업 중인 캐릭터도 플레이할 수 있어야 하기 때문이다.
반면 `chibi` 가 비면 로드가 실패한다. 그림 없는 가전은 화면에서 사라져 버려서 "게임이 깨졌다"로 보이기 때문이다.

## 스킬 동작 (`unit_behaviour`)

| 칸 | 뜻 |
| --- | --- |
| `defense` | 디펜스 전용 동작. **비우면 평범한 사거리 공격**을 한다 |
| `survLeader` | 대청소 리더 동작. 비우면 리더로 못 고른다 |
| `survComp` | 대청소 동료 동작. 비우면 공격하지 않는다 |
| `support` | 1 이면 지원형(대청소에서 적을 때리지 않고 리더를 따라다닌다) |
| `skp` | 이 동작이 읽는 `skill_param` 키 목록(쉼표 구분) |

지금 쓸 수 있는 값:

- `defense` — `vac` `melee` `fridge` `ac` `micro` `washer` `pc` `fan` `gen`
- `survLeader` — `vac` `robot` `ac`
- `survComp` — `vac` `robot` `fridge` `ac` `micro` `washer` `fan`

**동작을 빌려 써도 수치는 자기 것을 쓴다.** 새 가전이 `defense = vac` 이면 흡입 로직은
청소기 것을 쓰지만 반경·초당피해 등은 `skill_param` 의 **그 가전 id 행**에서 읽는다.
그래서 `skp` 에 적은 키를 채우지 않으면 로드가 실패한다.

목록에 없는 이름을 적으면 **로드가 실패한다.** 조용히 평타로 떨어지게 두면
기획 밸런스 문제처럼 보이지, 오타처럼 보이지 않기 때문이다.

## 상품

`dz_studio.py` 의 **상품** 탭이 `shop_product` 한 줄과 `reward_group` 보상 줄들,
그리고 이름·설명 문자열을 같이 쓴다. 보상은 `아이템ID, 개수` 를 한 줄에 하나씩 적는다.

현금 결제(`payKind = 1`)는 **테스트 공급자로만 구현돼 있다.**
실제 스토어 결제 SDK 는 아직 붙어 있지 않다.

## 코드가 필요한 경우

**새로운 종류의 동작을 만들 때만** C# 을 고친다. 동작은 수치가 아니라 로직이라서다 —
"반경 안의 적을 끌어당기면서 초당 피해를 준다" 같은 건 숫자로 표현할 수 없다.

고칠 곳:

1. `Core/Defense/UnitBehaviours.cs` — 동작 본체와 `Act` / `WantsSkill` / `OnSkillStart` 의 `switch`
2. `Data/TableValidator.cs` — `KnownDefenseKits` 에 새 이름 추가
3. `tools/dz_studio.py` — `DEFENSE_KITS` 에 새 이름 추가
4. `Tests/EditMode/CharacterDataTests.cs` — `BehaviourNamesAreAllReachable` 의 목록

**이미 있는 동작을 재사용하는 캐릭터는 코드를 전혀 건드리지 않는다.**

## 검사

`sync_to_unity.py` 가 변환하면서 테이블을 검사한다. 걸리는 것들:

- `unit_art` / `unit_behaviour` 행이 없는 가전
- 코드에 없는 동작 이름
- `skp` 가 요구하는데 `skill_param` 에 없는 값
- `lineCount` 와 실제 `string_ko` 대사 개수 불일치
- 비어 있는 이름·역할·스킬명 문자열 키

Unity 쪽 검사는 `CharacterDataTests` 가 맡는다. 데이터만 고쳐도 돌려 볼 수 있다.

```
Unity > Window > General > Test Runner > EditMode > CharacterDataTests
```

## 이미 있는 것 고치기 (2026-10-18)

캐릭터·상품 탭 왼쪽에 **목록**이 생겼다. 고르면 여섯 테이블에서 값을 다 읽어 와 칸을
채우고, 버튼이 `수정 내용 저장` 으로 바뀐다. `새로 만들기` 를 누르면 추가 모드로 돌아간다.

- **ID 는 바꿀 수 없다.** 여섯 테이블의 키라서 바꾸면 참조가 전부 끊긴다. 새 ID 가
  필요하면 `새로 만들기` 로 새로 만든다.
- 대사를 지우면 남은 `line` 키도 같이 지운다. 안 지우면 쓰이지 않는 대사가 테이블에 남는다.
- 소환 체크를 끄면 gacha_pool 에서 그 줄을 뺀다.
- 상품의 보상은 통째로 다시 쓴다. 줄을 지웠는데 옛 보상이 남아 있으면 상품이 말없이
  더 주게 된다.
- 가전을 주는 보상 줄(`# 가전 ...`)은 이 화면에서 고칠 수 없어 읽기 전용으로 보여 준다.
  그런 상품도 가격·제한은 고칠 수 있고, 보상 묶음은 건드리지 않는다.

### 수정 기능을 넣으면서 드러난 기존 버그

`상품 추가` 가 reward_group 에 **없는 열 이름**(`itemId`, `count`)을 쓰고 있었다.
실제 열은 `groupId, seq, kind, refId, min, max, prob` 다. 즉 **이 도구로 만든 상품은
보상 묶음이 비어 아무것도 주지 않았다.** 고쳤다. 이미 도구로 만든 상품이 있다면
해당 reward_group 행을 확인해야 한다.

### 검사

```bash
python tools/studio_roundtrip.py
```

모든 가전과 상품을 한 번씩 **불러왔다가 그대로 저장**하고 테이블을 통째로 비교한다.
한 글자라도 달라지면 실패다 — 불러올 때 읽지 않은 열은 저장할 때 날아가고, 화면에는
아무 신호도 뜨지 않기 때문이다. 이 검사가 위의 reward_group 버그를 찾아냈다.

`tools/DustZeroStudio.exe --selftest <파일>` 은 창 없이 exe 가 제대로 묶였는지 본다.
도구를 고친 뒤에는 `python tools/build_studio.py` 로 exe 를 다시 만든다.


## 스테이지 · 웨이브 (2026-10-19)

75판 목록에서 고르면 스테이지 수치와 그 판의 웨이브를 함께 불러온다.

**웨이브는 글로 고친다.** 한 줄이 한 등장이다:

```
# 시각(초), 적, 마리, 간격, 입구, 체력배수
3, dust, 3, 1, 1, 1
9, dust, 4, 0.9, 1, 1
```

한 판이 7~25줄이고 기획 작업은 보통 전체를 훑으며 숫자를 미는 식이라, 줄을 복사해
한꺼번에 바꾸는 편이 칸을 하나씩 클릭하는 것보다 빠르다. 대신 **저장할 때 한 줄씩
검사한다** — 없는 적, 범위를 벗어난 입구, 0마리, 칸 수 부족을 **줄 번호와 함께**
알려 주고 저장을 막는다. 글로 고치는 방식의 위험은 그것 하나뿐이라 거기에 검사를 몰았다.

타이핑하는 동안 위에 요약이 뜬다:
`16줄 · 총 69마리 · 마지막 등장 59초 · 1번 33마리 · 2번 20마리 · 3번 16마리`

입구 번호는 맵마다 다르다. 고른 맵의 입구 이름이 화면에 같이 나온다
(거실: 1 창문 · 2 베란다 · 3 현관).

**맵의 타일과 경로는 여기서 고치지 않는다.** 격자를 글로 편집하게 하면 사고가 난다.
있는 맵 중에서 고르기만 하고, 맵 자체는 `04_Stage.xlsx` 에서 고친다.

새 스테이지를 만들면 첫 클리어 보상(`firstRewardGroup`)과 해금 조건(`unlockCond`)은
0으로 남는다. 도구가 로그로 알려 주며, 필요하면 엑셀에서 채운다.


## 맵 격자 · 경로 (2026-10-19)

맵 15종. 격자는 **10행 × 7열 고정**이고, 타일과 입구별 경로를 같은 그림 위에서 고친다.

### 타일

| 글자 | 뜻 | 효과 |
| --- | --- | --- |
| `P` | 바닥 | 근접 가전을 놓는다. 적도 여기로 다닌다 |
| `H` | 가구 | 원거리 가전을 놓는다. 적은 못 지나간다 |
| `X` | 벽 | 아무것도 못 한다 |
| `E` | 목표 | 적이 닿으면 실점. **맵에 딱 하나** |
| `F` | 불 | 위에 놓인 가전이 과열된다 |
| `W` | 물 | 가전이 식는다. 적은 빨라진다 |
| `R` | 러그 | 적이 느려진다 |
| `O` | 기름 | 가전이 과열되고 적이 빨라진다 |

칸을 눌러 칠하고, 끌면 여러 칸을 한 번에 칠한다. 색은 게임이 쓰는 색과 같다 —
여기서 보는 것이 곧 전장에서 보일 것이어야 한다.

### 경로

입구마다 꺾은선 하나다. 칸을 누르면 꺾는점이 붙고, 오른쪽 버튼으로 지운다.
고르고 있는 경로는 주황색에 번호가 붙고 나머지는 회색이라 서로 가리지 않는다.
좌표는 `[열, 행]` 이다(행,열이 아니다 — 원본 데이터가 그렇다).

### 저장을 막는 검사

타일과 경로는 **서로 맞아야** 한다. 경로가 벽을 지나면 적이 벽을 통과하고, 목표에
닿지 않으면 그 입구로 들어온 적이 영원히 돌아다닌다. 글로는 그걸 확인할 방법이 없어서
격자 편집기를 만들었고, 저장할 때 다음을 막는다:

- 목표(E)가 0개이거나 2개 이상
- 경로가 비스듬하게 꺾임 (가로·세로로만 움직여야 한다)
- 경로가 지나는 칸이 벽이나 가구
- 경로의 마지막 점이 목표가 아님
- 꺾는점이 2개 미만, 경로 수와 입구 이름 수 불일치

**막지 않고 알림만 하는 것:** 입구가 맵 가장자리에 없는 경우. 처음에는 막는 규칙으로
넣었다가 기존 맵 두 개가 걸렸다 — 욕실의 배수구 `(1,3)` 과 덕트의 팬 구멍 `(3,1)`.
둘 다 바닥 한가운데에서 솟는 입구이고 그게 맞다. 게임에 없는 규칙을 만들어 멀쩡한
맵을 막을 뻔했다.

### 하지 않는 것

맵을 새로 만들거나 지우지 않는다. 입구 이름(`spawnKeys`)과 맵 이름도 여기서는 안 고친다.
`04_Stage.xlsx` 에서 한다. 맵을 고치면 **그 맵을 쓰는 스테이지가 전부 바뀐다** —
저장할 때 로그로 알려 준다.
