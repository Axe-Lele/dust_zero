# 디자인 전수 대조 — 방법과 한계

`production/qa/audit/REPORT.md` 가 결과다. 이 문서는 그걸 어떻게 만들고 무엇을 믿으면
되는지 적는다.

## "1px 일치" 는 달성할 수 없다

- 원본은 CSS **430×932**, 이식본은 uGUI **1080×1920**. 가로 배율 2.512, 세로 2.060 —
  **두 축의 배율이 다르다.** 그래서 어떤 좌표계를 기준으로 삼아도 다른 축이 어긋난다.
- 글꼴 래스터라이저가 다르다. 같은 글꼴·같은 pt 라도 자간과 글자 폭이 다르게 나온다.
- **TMP 의 줄 상자 규칙이 CSS 와 다르다.** CSS 는 `line-height` 로 줄을 자르고, TMP 는
  상자가 모자라면 자르지 않고 **아예 안 그린다.** 그래서 이식본은 모든 글자 상자를
  원본보다 크게 잡아야 한다. 이번 세션에서만 이 함정을 여섯 번 밟았다.

그러므로 목표는 "같은 픽셀" 이 아니라 **"같은 자리에서 시작하고 같은 크기로 보인다"** 다.

## 어떻게 재나

```
원본  →  tools/audit_extract_original.js  →  production/qa/audit/original/*.json
이식본 →  PlayModeSmoke.DumpLayout()      →  production/qa/audit/unity/*.tsv
                      ↓
            tools/audit_compare.py  →  production/qa/audit/REPORT.md
```

- 원본은 Playwright 로 **430×932** 에서 화면마다 `getBoundingClientRect` 와
  `getComputedStyle` 을 긁는다. 뷰포트를 틀리면 전부 틀린다 — 처음에 390 으로 재서
  모든 띠가 40px 넓다고 나왔고, 그건 **측정 실수지 이식 오류가 아니었다.**
- 이식본은 스크린샷을 찍는 **그 자리에서** 치수를 같이 적는다. 비활성 UI 는 레이아웃이
  안 돌아 있어 에디터에서 긁으면 거짓값이 나온다. 그래서 실행 중에 적는다.
- 양쪽 다 **CSS px** 로 환산해 비교한다.

## 짝은 글자로 찾는다

이름 규칙이 서로 다르다(`#wCoin` vs `TopBar/Coin/Value`). 그래서 **같은 글자를 가진
상자끼리** 짝짓는다. 숫자는 `#` 로 바꿔 비교하므로 `코인 2,000` 과 `코인 66.6K` 도 맞는다.
글자가 없는 판·아이콘은 `audit_compare.py` 의 `PAIRS` 에 사람이 적은 것만 본다.

## 보고서를 읽을 때

- **글자 상자는 시작 위치(dx·dy)만 본다.** CSS span 은 글자만큼, TMP 라벨은 준 상자만큼
  넓어져서 너비는 늘 다르다. 그걸 차이로 세면 216개 중 192개가 떠서 아무도 안 읽는다.
- **덩어리 단위가 다르면 큰 수가 나온다.** 예: 하단 탭의 `스테이지` 는 원본이
  아이콘+글자를 묶은 버튼(55×62)이고 이식본은 글자 라벨(61×17.5)이다. `dy +39` 는
  그 차이지 39px 어긋났다는 뜻이 아니다. 이런 것은 `PAIRS` 로 덩어리를 맞춰야 한다.
- 그래서 **실제로 볼 것은 같은 종류끼리의 dx·dy** 다.

## 상자가 아니라 **글자가 찍히는 자리**를 잰다

처음엔 요소 상자끼리 비교했고 홈 화면에서 7건을 "진짜 차이" 로 보고했다. **전부 틀렸다.**
원본의 `<b><img 아이콘>출석부</b>` 는 상자가 아이콘에서 시작하고 우리 라벨은 글자에서
시작한다. 그래서 `출석부` 가 16.8px 어긋난 것처럼 보였는데, 글자만 재면 **dx −0.2** 다.

그래서 양쪽 다 글자가 실제로 칠해지는 자리를 적게 했다.
원본은 `Range.getBoundingClientRect()`, 이식본은 TMP 의 `textBounds`.

단, **너비·높이는 두 쪽이 서로 다른 것을 잰다.** CSS 의 Range 는 advance 박스
(사이드베어링 포함), TMP 의 textBounds 는 칠해진 자리만이다. 그래서 우리 dw 가 늘
음수로 나오는데 글꼴이 좁은 게 아니다. **글자는 dx·dy 만 비교한다.**

## 고친 것 — 하단 탭 줄

| | 원본 | 고치기 전 | 고친 뒤 |
| --- | ---: | ---: | ---: |
| 칸 너비 | 55.1 | 61.4 | **55.1** |
| 칸 간격 | 57.1 | 61.4 | **57.1** |
| 첫 칸 x | 16.0 | 0.0 | **16.0** |
| 글자 dy | — | +4.6 | **+0.6** |

원본은 탭 줄을 **좌우 16px 안쪽**에 두고 2px 간격으로 7칸을 나눈다. 우리는 0~430 을
그냥 7등분했다. 그래서 탭 글자가 왼쪽 −5.3px 에서 오른쪽 +14.5px 까지 **점점** 밀렸다.
한 칸만 보면 안 보이고 여섯 칸을 늘어놓고 재야 보이는 종류의 어긋남이다.
글자 아래 여백도 원본 8 에 우리 4.2 였다.

고친 뒤 탭 x 는 16.0 / 73.1 / 130.3 / 187.4 / 244.6 / 301.7 / 358.9 로, 원본의
16.0 / 73.1 / 130.3 / 187.4 / 244.6 / 301.7 / 358.8 과 **0.1px 안에서 같다.**
홈 화면 차이 20건 → **7건**(전부 9px 이하), 전체 166 → **133**.

## 아직 보지 않는 것

- **색.** 양쪽 다 뽑아 두었지만(원본 `bg`, 이식 `color`) 비교는 아직 안 한다.
- **글자 없는 상자.** `PAIRS` 에 적은 셋(상단바·하단바·전투 HUD 판)만 본다.
  그 셋은 전부 **정확히 일치**한다(398×64 @16,12 등).
- **보드와 아레나.** 이식본은 카메라로 그려 UI 상자가 없다.
- 결과 화면 2종·장비 화면 4종은 이식본 치수는 있고 **원본 쪽을 아직 안 긁었다.**

## 틀렸던 것 — 글꼴 소동

중간에 "본문 글꼴이 전부 DoHyeon 으로 잘못 만들어져 있다" 고 판단했는데 **그것도 틀렸다.**
`.asset` 의 GUID 를 grep 으로 엉뚱한 줄에서 읽었다. 제대로 읽으면
Body = IBMPlexSansKR-Regular, Number = SemiBold, Title = DoHyeon 으로 **처음부터 맞았다.**

다만 그 과정에서 `MakeFont` 의 진짜 위험을 찾아 고쳤다 — 자산이 있으면 **어떤 ttf 로
만든 것인지 보지 않고** 그냥 돌려줬다. 의도를 바꿔도 옛 자산이 조용히 계속 쓰인다.
이제 원본 ttf 가 다르면 지우고 다시 만들고, `FontAssetTests` 두 개가 지킨다.
**이 테스트는 통과하는 것만 봤다** — 깨지는 걸 본 적이 없으니 지킨다는 보장은 아직 없다.

## 비교하면 안 되는 것

스테이지 탭처럼 **스크롤되는 목록**은 두 쪽의 스크롤 위치가 달라 수백 px 차이로 나온다
(`욕실` dy −455). 자리 차이가 아니라 "같은 지점을 보고 있지 않다" 는 뜻이다.
목록은 첫 행 기준으로 맞춘 뒤에 비교해야 한다. 아직 안 했다.
