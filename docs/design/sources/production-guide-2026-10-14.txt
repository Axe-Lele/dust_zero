
오퍼레이션: 더스트 제로 유니티 제작 가이드
2026년 10월 14일 · @정의론
HTML 프로토타입(전투·아웃게임·방치형·데이터 테이블 16종)을 유니티로 옮기기 위한 정리입니다. 이 문서의 수치와 규칙은 프로토타입과 테이블 생성 스크립트(gen_tables.py)가 원본이에요.
• 프로토타입: 더스트 제로
• 플레이 테스트 묶음: dustzero_play.zip (index.html 더블클릭으로 실행, data/ 테이블 17종, tools/gen_tables.py·pack_tables.py, README.txt)
확정된 설계
가전을 모에화한 캐릭터를 모아 집을 지키는 방치형 수집 디펜스입니다. 지금까지 정한 방향은 아래와 같아요.
항목
결정
콘셉트
오리지널 IP. 가전 기능이 곧 스킬(청소기=흡입, 에어컨=둔화, 컴퓨터=버프)
아트
인게임은 SD(2.3등신, Spine), 가챠·상세는 성인 일러스트. 가디언 테일즈식 이원화
전투
명일방주식 타일 디펜스. 근접은 바닥(경로), 원거리·지원은 가구 위에 배치
몬스터 공격
HP 대신 과열. 저지 중 과열이 쌓이고 가득 차면 5초 정지하며 적을 놓침. 죽지 않음
스킬
게이지가 차고 조건이 맞으면 자동 발동. 수동 조작 없음
진행
방치형. 깬 최고 스테이지에 비례해 자동 청소 시급 상승. 반복 클리어 보상 없음
재도전 동기
스테이지별 최고 별 기록 + 챕터 별 누적 보상(5/10/15)
성장
레벨(코인+계열 부품 2단 비용), 돌파(가전 조각+코인, 최대 5, 레벨 상한 해제)
엔진
유니티(모바일 결제·광고 SDK, Spine 런타임, Addressables)
작업 환경
집 개인 PC, 개인 계정·저장소. 회사 장비·시간·자료와 분리
프로토타입은 브라우저에서 그대로 플레이할 수 있어요. 유니티 작업 중 "이 상황에서 어떻게 동작해야 하지?"가 헷갈리면 프로토타입에서 직접 확인하는 게 가장 빠릅니다.
전투 규칙
맵은 7×10 타일이고 입구가 3곳입니다. 지상 적은 바닥 칸 격자 위에서 목표물(소파, 식탁, 욕조)까지 가장 짧은 길을 매 틱 다시 계산해 걷고, 근접 가전이 서 있는 칸은 피해 돌아갑니다. 돌아갈 길이 아예 없을 때만 가전과 맞붙어 저지되거나 줄을 섭니다. 비행 적은 입구별 고정 경로로 날아요. 웨이브마다 열리는 입구가 바뀌고(처음 18초는 1곳, 30초부터 3곳 모두), 적이 나오기 3초 전부터 해당 입구에 붉은 카운트다운이 떠요. 입구 앞 2칸과 목표물 바로 앞 칸에는 근접 가전을 둘 수 없습니다. 괄호 안은 테이블 컬럼이에요.

자원과 배치
• 전력: 시작 1,000W, 초당 +100W, 최대 9,900W. 발전기 1대당 초당 +35W 추가(풀가동 중 2배). 내부 값은 100W = 1 (startPower, regenPerSec, skill_param의 gen)
• 동시 배치 최대 8대 (maxUnits)
• 철수하면 배치 비용의 50% 환급, 같은 가전은 12초 뒤 재배치 (redeployCooldown)
• 청결도 10에서 시작. 적이 목표물에 닿으면 무게만큼 감소(일반 1, 보스 2). 0이 되면 패배 (lifeMax)
• 마지막 웨이브까지 나오고 적이 모두 사라지면 승리
전투 중 강화와 멀티탭 (unit_boost, config.multitapCost)
• 배치가 다 찬 뒤 남는 전력을 쓰는 곳. 봇 기준으로 8칸이 30~45초에 차고, 이후 한 판에 4,000~9,000W가 남아 버려지고 있었음
• 강화: 놓인 가전을 눌러 그 판에서만 2단계(배치 비용 ×1.0) → 3단계(×1.5). 능력 배율 ×1.35 / ×1.75(공격·스킬 피해·과열 한도·냉각·발전·버프)
• 3단계 보너스: 근접 저지 +1, 원거리 사거리 +0.4칸, 컴퓨터·선풍기 범위 +0.4칸, 스킬 충전 −10~20%
• 멀티탭: 배치 칸 8 → 9 → 10, 2,000W / 3,500W
• 철수 환급은 배치+강화에 쓴 전력 전체의 50%
• 후반 압박(wave.hpMul): 마지막 웨이브 시각의 40%부터 적 HP가 올라 마지막 웨이브 ×3. 1-1 튜토리얼과 보스는 제외
• 숙련 봇에 '남는 전력은 가장 덜 강화된 핵심 가전부터 강화' 규칙을 넣고 스테이지 hpMul 재보정. 강화를 안 쓰면 보스 판 남은 청결도가 1-5 5.5 → 2.6, 2-5 4.9 → 3.1로 떨어짐
저지와 과열
• 근접 가전은 경로 위 자기 위치 ±0.4칸에 들어온 땅 적을 저지 수(block)만큼 붙잡아요. 보스는 저지 2칸을 차지합니다.
• 비행 적(초파리)은 저지되지 않아요. 가전마다 평타 대상과 스킬 대상이 지상·공중·모두 중 하나로 정해져 있고(unit.atkTarget, skillTarget), 청소기·로봇청소기는 둘 다 지상, 냉장고는 평타 지상·스킬 모두, 원거리는 모두예요. 지상 적은 우회형(돌아갈 길이 있으면 피해 가고 막혔을 때만 공격: 먼지뭉치)과 직진형(길을 막은 가전을 밀고 들어옴: 기름때, 고팡이, 보스)으로 나뉩니다(enemy.ai).
• 붙잡힌 적은 공격 간격(itv)마다 공격력(dmg)만큼 과열을 쌓아요. 저지 정원이 차면 뒤에 오는 적은 통과하지 않고 줄을 서며, 줄 선 적도 공격력의 50%만큼 과열을 쌓아요(queueHeatRatio).
• 과열은 자연적으로 초당 25 식고, 주변 선풍기·물기 칸이 냉각을 더합니다.
• 과열 한도(heat)에 닿으면 5초간 정지(overheatSec): 붙잡던 적과 줄 선 적을 한꺼번에 풀어버리고, 공격·스킬이 멈추고, 진행 중인 스킬도 끊겨요. 한도만큼 식으면 복구합니다.
스킬
• 스킬 게이지는 초당 1씩 차고, 가득 찬 뒤 발동 조건이 맞으면 자동으로 씁니다(헛방 방지).
• 발동 조건: 공격형은 사거리 안에 적이 있을 때, 로봇청소기는 자기 과열 50% 이상, 선풍기는 주변 가전 과열 40% 이상, 컴퓨터는 버프 범위 안에 공격 가전이 있을 때.
• 성장 배율 = 1 + 0.05×(레벨−1) + 0.12×돌파. 공격력, 과열 한도, 냉각량, 스킬 피해에 곱해요 (lvBonus, starBonus).
• 컴퓨터 버프: 평소 1.6칸 안 공격력 +25%, 스킬 중 2.4칸 안 +60%에 공격 속도 2배. 여러 대면 합산됩니다.
별
• 승리 시 남은 청결도가 1 이상이면 ★, 6 이상 ★★, 10이면 ★★★ (starLifeMin)
• 스테이지마다 최고 기록만 저장하고, 기록이 오르면 챕터 별 합계도 오릅니다.
가전과 적
가전 9종(R 4, SR 3, SSR 2)과 적 7종(보스 3)입니다. 수치는 레벨 1, 돌파 0 기준이에요.

스테이지 구성 (stage.json, wave.json)
• 3챕터 × 5스테이지 = 15. 챕터마다 맵 하나(거실, 주방, 욕실)를 쓰고, x-5는 보스 스테이지
• 적 HP 배율은 스테이지별 보정값(1-1 ×0.84 ~ 3-5 ×1.18). 기준 덱(발전기 포함)과 기준 레벨(Lv ≈ 스테이지 순번)로 시뮬레이터를 돌려, 숙련 플레이의 평균 남은 청결도가 1-1 약 9, 챕터 1 약 6~7, 챕터 3 약 6, 보스 약 4~6이 되도록 맞췄어요. 웨이브 구성과 입구 배치가 스테이지마다 달라서 배율이 단조 증가하지는 않습니다
• 챕터 안에서 스테이지마다 웨이브 적 수 +8%. 웨이브는 5~6초마다 시작해 쉬는 구간이 거의 없고, 같은 웨이브 안 간격은 0.8초 이상(더 촘촘하면 공격 속도가 못 따라가 체력과 무관하게 샘). 처음 여는 입구는 경로가 긴 두 곳을 번갈아 씀
• 스테이지 길이: 1-1 튜토리얼 약 45초(19마리), 일반 약 65~85초, 보스 약 90~100초 (이전 90~125초)
• 해금은 이전 스테이지 클리어 조건(condition.json)
• 첫 클리어 보상: 코인 1,000 + 400×(n−1), 크리스탈 100. 보스는 크리스탈 300 + 부품 4종 각 15
• 재도전 승리는 보상 없음. 별 기록만 갱신
자동 청소 (방치 보상)
• 1-1 클리어 시 개방(content_unlock.json)
• 시급은 클리어한 최고 스테이지 행의 idleCoin/idlePart/idleCrystal을 쓰고, 최대 12시간까지 누적 (idleCapHours)
• 새 스테이지를 깨면 그때까지 쌓인 몫을 예전 시급으로 확정(bank)하고 새 시급을 적용

데이터 테이블
테이블의 원본은 엑셀(tables/01_Config ~ 06_Gacha.xlsx, 시트 이름 = 테이블 이름)이고, python tools/build.py 로 data/*.json과 data/tables.js를 만듭니다. 유니티에서도 같은 JSON을 씁니다. gen_tables.py는 공식으로 엑셀을 처음부터 다시 만드는 도구라 엑셀 수정분을 덮어씁니다.
규약
• PK 컨럼 이름은 항상 id. 여러 행이 한 묶음인 테이블은 groupId + seq
• enum은 enums.json 하나가 유일한 원본. 다른 테이블은 정수값만 쓰고, C# enum도 여기서 자동 생성
• 사람이 읽는 문자열은 string_ko.json에만. 다른 테이블은 *Key 컨럼으로 참조
• 보상은 전부 reward_group(kind, refId, min, max, prob), 비용은 costItem + costCount
• 해금은 테이블마다 조건을 새로 정의하지 않고 condition id 하나만 참조
• 컨럼은 위치가 아니라 이름으로 읽고, 변경 검증은 행 수가 아니라 diff로

유니티로 읽는 법
1. JSON을 Assets/Data/Tables에 둔다(개발 중에는 TextAsset, 라이브에서는 Addressables로 원격 갱신).
2. 테이블마다 행 클래스(UnitRow 등)를 만들고 Newtonsoft.Json으로 역직렬화한다.
3. 부팅 때 TableDB가 전부 읽고, id로 찾는 Dictionary를 만든다. 참조 무결성(없는 id, 빈 그룹)을 여기서 검사해 로그로 남긴다.
4. enums.json에서 C# enum 파일을 만드는 에디터 메뉴(Tools/Generate Enums)를 두면 원본이 하나로 유지된다.
[Serializable] public class UnitRow {
    public string id; public int order; public int rarity; public int family; public int tile;
    public int cost; public float heat; public float atk; public float itv; public float range;
    public int block; public float sp; public float dur; public float cool; public int lineCount;
    public string nameKey, shortKey, roleKey, skillKey, descKey;
}

public static class TableDB {
    public static Dictionary<string, UnitRow> Unit;
    public static Dictionary<int, List<RewardRow>> RewardGroup;
    public static void Load() {
        Unit = Read<List<UnitRow>>("unit").ToDictionary(r => r.id);
        RewardGroup = Read<List<RewardRow>>("reward_group").GroupBy(r => r.groupId)
            .ToDictionary(g => g.Key, g => g.OrderBy(r => r.seq).ToList());
        // ... 나머지 테이블
    }
    static T Read<T>(string name) =>
        JsonConvert.DeserializeObject<T>(Resources.Load<TextAsset>($"Tables/{name}").text);
}
엑셀 규약: '#'으로 시작하는 시트와 A열이 '#'인 행은 변환에서 빠지고, 1행은 컨럼 키, 2행은 설명입니다. 맵 경로는 map_entrance 시트에 "0,2 > 1,2 > ..." 형식으로, 타일은 map_tile 시트에 행별 7글자로 적습니다.

6. 승패 판정
