- **새 시스템 6개**(퀘스트 · 미션/업적 · 스토리+미니게임 12종 · 호감도 · 우편 ·

  800줄이 넘는다. 리그·타워·협동을 합친 것보다 크다.

  필요하다(기존 `tools/convert_art.py` 는 낱장 기준이다).

## 5. 아직 안 한 것 / 결정이 필요한 것

- **버전 사본을 만들지 않았다.** 지금까지는 `GameData/versions/<버전>/` 에 원본을
  통째로 복사하고 해시를 적어 왔다(10.19-e 는 8.6 MB). 10.22-g 는 **116 MB** 이고
  그중 약 98 MB 가 `art/261022*/source/` 의 원본 PNG 48장이다. git 에 그대로
  넣으면 저장소가 그만큼 커진다. **사용자 결정 사항** — 전부 넣을지, `source/` 를
  빼고 런타임 에셋만 넣을지(약 18 MB), 사본을 만들지 않을지.
- 데이터 반영(`GameData/data`, StreamingAssets), 엑셀 충돌 확인, 세이브 마이그레이션은
  전부 미실시다.
- 원본 쪽 "결과 동일" 주장과 밸런스 수치는 우리가 다시 돌려 보지 않았다.

## 7. 엑셀 충돌 점검 (2026-10-23)

점검 방법: `xlsx_io.py` 의 `WORKBOOKS` 선언을 양쪽에서 읽고, **파일 안의 실제 시트**도

그러면 build 가 조용히 빈 표를 내보낸다. 결과는 양쪽 다 **어긋난 권 0** 이다.

### 충돌은 아니지만 같이 처리해야 하는 것

- **`04_Stage.xlsx` 에 `stage_hard` 시트가 생겼다.** 우리도 쓰는 권이라, 상류 파일을

  쓰므로 **확인 없이 덮으면 맵이 깨져도 모른다** — 덮기 전에 무손실 왕복을 먼저 확인한다.
- **`xlsx_io.py` 는 우리가 고친 게 딱 두 군데다.** ① `WORKBOOKS` 에 Character 한 줄
  ② `write_workbooks(..., only=None)` 와 그 걸러내기 한 줄. 상류는 10.19-e → 10.22-g
  사이에 6군데를 고쳤다(04_Stage 시트, 새 워크북 4, DESC 새 표 10개, tutorial 의 `who`,
  CONFIG_NOTE 새 키 14개, `battleTimeScale`). **상류 파일을 받아 우리 두 줄을 다시
  얹는다** — 반대로 하면 상류 변경을 손으로 베끼게 되고, 그러면 틀린다.
  (지금 우리 파일에는 12_Coop 주석이 Character 줄 끝에 붙어 있다. 옮길 때 같이 고친다.)

### 덤으로 찾은 것 — 우리 `gen_tables.py` 는 10.14-d 시절 것이다

지금은 무해하다 — `build.py` 는 엑셀만 읽고 `gen_tables` 를 부르지 않는다. 그러나

받을 때 같이 올리거나, 아예 지우고 "상류 버전 사본에서 꺼내 쓴다"로 정하는 편이 낫다.

`tables.js` 가 약 13% 커진다). 게임 동작에는 영향이 없다.

### 손댈 필요 없는 것

`sync_to_unity.py` 는 표 목록을 `xlsx_io.WORKBOOKS` 에서 **뽑아 쓴다.** 새 표 11개가
자동으로 따라온다. 반면 Unity 쪽 `TableRows.Names` 는 손으로 적은 목록이라, 실제
이식할 때 11개를 등록해야 한다(등록하지 않으면 StreamingAssets 만 늘고 게임은 모른다).
