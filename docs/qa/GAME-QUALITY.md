# 게임 완성도 검증 절차

이 절차는 기존 CCGS 작업 흐름을 보완한다. 기능 단위 구현 완료 후 `/game-quality <기능>`을 실행한다.
최종 제출 전에는 전체 항목을 적용한다. 현재 문서 설치는 게임 테스트 통과를 뜻하지 않는다.
`docs/design/NEW-BUILD.md`의 최신 기준을 먼저 읽고 보고서에 비교 빌드를 명시한다.
현재 GameData의10.14-d와 신규10.15-h를 혼합하지 않는다. 신규 구현의 원본 비교는10.15-h로 수행한다.

## 공통 실행 순서

변경 범위와 합격 기준 기록 → 컴파일 → 관련 자동 테스트 → Unity 실제 플레이 →
원본과 화면/규칙 비교 → 결함 수정 → 영향받은 항목 재검증 → 증거와 한계 기록.

- Unity가 열려 있으면 Unity MCP의 프로젝트 경로부터 확인하고 에디터 내 테스트를 실행한다.
- 닫혀 있으면 Git Bash에서 `bash tools/ccgs-unity.sh compile`, `bash tools/ccgs-unity.sh test`를 사용할 수 있다.
- 기존 test 진입점은 EditMode와 PlayMode 모두 실제 통과 결과를 요구한다. 미구현 PlayMode 스위트는 미확인이다.
- 열린 에디터에 배치 실행을 중복하지 않는다. `build`/`run` 진입점의 현재 구현 상태도 확인한다.
- 콘솔의 새 에러/예외를 확인한다. 기존 오류는 별도로 기록하고 새 오류와 혼동하지 않는다.
- 코드 읽기, 컴파일, 스크린샷 한 장만으로 플레이 성공을 대신하지 않는다.

## 범위별 합격 기준

| 범위 | 필요한 검증 |
| --- | --- |
| 디펜스 | 로비→편성/배치→웨이브→승패→결과→로비. 배치 금지 칸, 전력 부족, 철수/재배치, 지상 우회와 비행 경로, 저지/과열/냉각, 스킬 대상, 일시정지/배속, 클리어와 실패 각각 확인 |
| 성장·보상 | 첫 클리어/별 보상/중복 유닛/재화 소모가 원본 규칙과 일치. 결과 버튼 연타·재진입·재실행으로 보상을 중복 지급하지 않는지 확인 |
| 저장 | 별도 테스트 프로필로 저장→앱/플레이 종료→재실행→진행/재화/편성 복원. 손상 파일 복구는 임시 테스트 경로에서만 확인. 실제 사용자 저장을 초기화하지 않음 |
| 생존 모드 | 신규10.15-h는 5분 이후 계속→사망/명시적 종료→결과. 포자·보스·선택·협동기·계열·일일 구간 보상·150상한·30초미만 횟수 미소모 확인. 구버전5분 종료는 구버전 회귀 검사에만 사용. 시간 단축/디버그 여부를 명시 |
| 전투 강화 | 2/3단 비용·배율, 멀티탭8→9→10, 강화 후 철수 환급, 범위/저지/충전/발전 효과와 후반 wave.hpMul |
| 상점·패스 | 테스트 결제/광고 성공·취소·실패·중복 콜백, 일일/주간/계정 제한, 구매복구·구독·시즌·소급수령. 일반 재클리어 보상 없음과 패스XP30 구분 |
| UI·입력 | 한글 누락/네모 글자 없음, 텍스트 넘침/버튼 겹침 없음, Safe Area, 팝업 닫기/뒤로가기, 입력 차단, 터치/마우스 중복 발동 없음 |
| 연출·소리 | 피격/스킬/승패 피드백을 실제 재생으로 확인. 효과음 중첩/음소거/음량 설정 확인. 화면을 확인하지 않은 임시 도형은 최종 자산으로 표시하지 않음 |
| 성능 | 대표 전투와 적 다수 상황을 측정. 장치/해상도/빌드 종류/프레임 시간/GC/메모리 기록. 목표 FPS와 적 수를 먼저 명시. 에디터 수치로 실기기 성능을 보장하지 않음 |
| 최종 빌드 | 실제 타깃 빌드 생성→실행→핵심 흐름 완주. 개발 기능/디버그 UI 노출, 누락 씬/에셋, 저장 경로, 종료/복귀 확인 |

작은 수정에서는 영향 있는 항목만 수행하고 제외 이유를 적는다. 전체 게임 완료를 선언할 때는
두 게임 모드, 저장/보상, UI, 성능, 실제 빌드 항목을 제외하지 않는다.

## 원본 비교

프로젝트 루트에서 실행한다. 포트가 사용 중이면 `--port 8766` 등 다른 포트를 사용한다.

```powershell
python tools/serve-original.py --port 8765
```

URL: `http://127.0.0.1:8765/original_index.html`.
이 서버는 프로젝트의 `GameData/` 사본을 제공하며 원본 파일을 수정하지 않는다.
주의: 이 경로는 최초10.14-d용이다. 신규 비교는 NEW-BUILD.md의 별도 서버/URL을 사용하거나
개발자가 버전 사본을 만든 뒤 서버 경로를 그 사본으로 명시적으로 변경한다.
Playwright는 독립된 임시 브라우저를 사용한다. 브라우저를 닫으면 이 테스트의 저장 상태가 사라진다.
저장 복원 비교가 필요하면 해당 테스트의 storage state만 증거 폴더에 저장하고 다시 불러온다.
평소 사용하는 Chrome/Edge 프로필과 연결하지 않는다.

1. 같은 스테이지·편성·진행 조건을 맞추고 화면 전환과 표시 수치를 기록한다.
2. 기본 비교 크기는 390×844이며 좁은 360×800, 긴 412×915에서도 확인한다.
   이 값은 검사 뷰포트 예시이며 타깃 장치 성능이나 Safe Area를 대신하지 않는다.
3. Playwright의 screenshot/vision 기능으로 원본 Canvas와 DOM UI를 함께 확인한다.
4. Unity의 해당 화면을 캡처하고 정보 계층, 여백, 폰트, 색상, 캐릭터 식별성, 버튼 피드백을 비교한다.
5. 무작위 결과는 같은 시드/고정 테스트 입력을 사용할 수 있을 때만 수치를 직접 대조한다.
   그렇지 않으면 공통 규칙과 범위를 검증하고 다른 결과를 버그로 단정하지 않는다.
6. 폰트 등 네트워크 리소스 실패와 실제 게임 오류를 구분해 기록한다.

## 문서 조회

Context7의 `resolve-library-id`로 라이브러리를 찾고 `query-docs`로 필요한 API만 조회한다.
Unity 공식 문서나 Unity-Technologies 저장소를 우선하고 출처 URL/대상 버전을 기록한다.
현재 `ProjectVersion.txt`와 `Packages/manifest.json`을 기준으로 한다.
다른 버전의 예제를 그대로 적용하거나 문서 조회 때문에 패키지를 업그레이드하지 않는다.
무료 익명 조회 제한에 걸리면 공식 문서 조회로 이어가고 제한 사실을 기록한다.

## 증거와 완료 판정

`production/qa/evidence/<날짜시각>-<기능>/`에 보고서, 테스트 결과, 화면, 로그를 모은다.
REPORT-TEMPLATE.md를 사용하며 이전 실행의 결과를 이번 검증으로 재사용하지 않는다.
PASS에는 증거가 필요하다. 미실행·접속 실패·아직 없는 씬/테스트는 UNVERIFIED로 기록한다.
필수 항목 하나라도 실패하면 FAIL, 필수 미확인이 남으면 UNVERIFIED다.
그래픽 임시 상태와 실제 기기 미검증을 최종 보고에서 명시한다.
