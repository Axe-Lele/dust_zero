### 원인

`FrameCamera` 가 **HUD 띠와 트레이 띠 사이의 남는 자리를 전부** 판에 줬다.
그 자리(125~790)는 원본 상자(135~695)보다 95px 크다. 띠를 정확히 재고 있었지만
*재야 할 대상이 틀렸다* — 원본은 남는 자리를 쓰지 않고 고정 상자를 쓴다.

### 고친 것

`BoardStrip()` 을 새로 두고 전투 중에는 원본 상자(`Py(135)` 위, `Py(560)` 높이,
`Px(398)` 폭)를 쓴다. 브리핑은 패널과 버튼 줄이 자리를 달리 먹으므로 전처럼 띠를 재서 쓴다.
`CentreBoardInStrip` 과 `CurrentBandAspect` 도 같은 자리를 보도록 묶었다.

재측정: 판 CSS **145.8 ~ 684.2** (원본 135~695 안). 트레이와 겹치지 않는다.
브리핑도 그대로다 — 판 바닥 1720 / 버튼 줄 1745 (화면 아래에서 잰 값).

### 같이 고친 것

`ContentTab.poolFill` 배선이 비어 있었다. `UiKit.Bar` 는 채움을 `RectTransform` 으로 주는데
필드는 `Image` 라 `Wire` 가 넣지 못했다. 이전 작업에서 넘어온 것이고 EditMode 를 막고 있었다.

## 협동 알림 겹침 (2026-10-21)

### 원본 규칙

`index.html` 의 떠오르는 글 그리기:

```js
if (tx.label){ font = 700 max(11, k*0.22)px 'IBM Plex Sans KR'
               w = measureText + 12;  X = clampX(w)
               rr(ctx, X-w/2, Y-10, w, 20, 10, 'rgba(29,34,38,.85)')   // 어두운 알약
               fillText(...) }
else { sz = tx.big ? k*0.36 : max(11, k*0.22); font 'Share Tech Mono'; 외곽선 }
```

읽을 것이 네 가지다:

1. **라벨이면 `big` 을 무시한다.** 항상 `k*0.22`.
2. 라벨 뒤에 **어두운 둥근 알약**을 깐다. 겹쳐 떠도 읽히는 건 이것 덕이다.
3. `clampX` 로 **판 안에 가둔다.**
4. 라벨은 본문 글꼴, 숫자는 숫자 글꼴.

### 우리가 틀렸던 것

`FxLabel.Init` 이 `e.Big ? 5.2 : e.Label ? 3.4 : 3.2` 였다. 협동은 합치기·바꾸기를
`big:true, label:true` 로 알리므로 **`big` 이 이겨 0.52칸** 으로 그려졌다 — 원본의 2.4배다.
알약도 없고 가두지도 않아, 합치기가 몰리는 순간 가전 이름이 판을 통째로 덮었다.

고친 것: 크기를 `label → 2.2 · big → 3.6 · 보통 → 2.2` 로(원본과 같은 `k` 배수),
라벨에 어두운 알약을 깔고, 라벨 글꼴을 본문으로, `FxDirector.LabelClampMinX/MaxX` 로
판 안에 가둔다(전투 화면이 판 가로 범위를 넘겨 준다).

재확인: 35·36 에서 이름이 알약에 담겨 읽히고 판 밖으로 나가지 않는다.

### 아직 남은 것

- **피해 숫자가 여전히 뭉친다.** 크기는 원본과 같지만(`k*0.36`) 원본은 숫자에
  `lineWidth 3` 외곽선을 넣어 밝은 바닥 위에서도 구분된다. TMP 외곽선은 머티리얼
  인스턴스가 필요해 그대로는 못 넣는다 — 숫자용 머티리얼을 따로 만들어야 한다.
- **협동 HUD 캡션이 아직 잘린다**(`고리 …`, `버틴 웨…`). `SetCoopChrome` 이
  `lifeReadout.minWidth` 를 84 → **108** 로 올렸는데도 그대로다. 배선은 맞고(6451행),
  행도 `childControlWidth` 에 가운데만 flexible 이라 min 이 지켜져야 한다.
  **원인 미확인** — 다음에 협동을 띄워 놓고 실제 rect 를 재서 볼 것.

EditMode **175/175** · PlayMode **7/7**.

### 협동 HUD 캡션 — 원인

읽기칸 폭을 **두 곳에서 쓰고 있었다.**

- `SetCoopChrome(true)` 가 협동 머리글에 맞춰 `lifeReadout.minWidth` 를 넣고
- `SyncHud` 가 **매 프레임** `UiTheme.FitToText(..., Px(30))` 로 같은 칸을 다시 쟀다.

`FitToText` 는 **숫자만** 보므로 `max(Px(30), '0' 의 폭)` = 61.8 이 되어, 들어간 값이
한 프레임 만에 덮였다. 그래서 폭을 84 → 108 로 올려도 화면은 그대로였다.

재어서 확인한 과정: 협동을 띄워 놓고 `lifeReadout.minWidth` 를 읽으니 61.8(= `Px(30)`,
협동이 **아닐 때**의 값)이었다. `SetCoopChrome(true)` 를 직접 부르면 222.5 가 되고,
몇 프레임 뒤 다시 61.8 로 돌아갔다. 그런데 `_coop` 은 살아 있고 `coopBars` 도 켜져 있어
`SetCoopChrome(false)` 가 돈 것은 아니었다 — 남는 범인은 매 프레임 도는 `SyncHud` 뿐이었다.

고친 것: `FitToText` 가 **머리글도 함께 보고** 둘 중 넓은 쪽에 맞춘다. 쓰는 곳이 하나가
되도록 `SetCoopChrome` 의 폭 지정은 걷어냈다.

확인: `고리 먼지 / 40` → 칸 135.5 / 글자 10자 전부, `버틴 웨이브` → 105.0 / 6자 전부.

### 피해 숫자 외곽선 (2026-10-21)

원본은 숫자를 `lineWidth 3` · `rgba(29,34,38,…)` 로 두르고 그 위에 색을 칠한다.
밝은 바닥에서 숫자가 겹쳐도 서로 구분되는 건 이것 덕이다. 우리는 외곽선이 없어
흰·주황 글자가 뭉쳤다.

TMP 외곽선은 머티리얼이 필요하다. `fontMaterial` 에 손대면 **객체마다 인스턴스**가 생겨
배칭이 깨지고, 글꼴의 공용 머티리얼을 고치면 **게임의 모든 숫자**에 외곽선이 생긴다.
그래서 `Assets/DustZero/Settings/NumberOutlined.mat` 를 한 장 구워 공유한다
(`OutlinedNumberMaterial`). `FxLabel` 은 **숫자일 때만** 그 머티리얼을 쓰고,
라벨은 글꼴이 다르므로 제 글꼴의 머티리얼을 쓴다.

**두께는 재서 정했다.** 처음 넣은 0.15 는 눈으로는 "안 들어갔나" 싶었는데, 글자 둘레의
최저 밝기를 재니 94 였다(외곽선 색은 34, 외곽선 없는 쪽은 117) — 들어가긴 했으나
거의 안 보이는 수준이었다. 0.35 에서 33.7 이 되어 선이 제 색으로 또렷해졌다.

확인: 협동 판에서 겹친 숫자가 각각 읽힌다.

썼다. 창이 1080x1920 일 때는 둘이 같아 맞았지만, 비율이 다르면 어긋나 판이 기둥을 넘어
카드 줄까지 흘렀다.

고친 것:

- `UiTheme.ScreenPerPage` / `PageViewport` 를 두어 **화면 픽셀**로 재게 했다. 판 상자와
  아레나 뷰포트가 이걸 쓴다.
- 캔버스 스케일러를 **Expand** 로. 가로에 맞추면(예전) 긴 화면에서 캔버스 세로가 1920 을
  넘어 세로 치수가 밀리고, 세로에 맞추면 원본보다 좁은 화면(720x1600 = 0.45)에서 886 기둥이
  캔버스 폭(864)을 넘어 잘린다. **둘 중 작은 쪽에 맞춰야** 둘 다 막힌다.
  이건 테스트가 잡아 줬다(`CanvasScalerTests`).
- 기둥을 세로도 페이지 크기(1920)로 고정하고 가운데 두었다. 캔버스를 꽉 채우면 화면이
  페이지보다 길 때 아래에 붙인 것들이 페이지 밖으로 내려가 카메라와 어긋난다.
- **판이 창 크기 변화에 다시 잡히지 않았다.** 다시 잡는 조건이 "띠의 가로세로 비"였는데
  자리를 고정 상자로 바꾼 뒤 그 비가 **상수**가 되어 버렸다. 화면 크기와 자리를 비교하도록 바꿨다.
- 판 카메라에 기둥 뷰포트를 주고, 여백을 칠할 `Backdrop` 카메라를 두었다.
- **대청소 카메라가 평소에도 켜져 있었다.** 화면 전체를 제 배경색으로 칠하고 아레나 바닥까지
  그려, 로비·전투의 좌우 여백에 그 무늬가 비쳤다("뒷배경이 갱신 안 된다"). 대청소 중에만 켠다.

세 비율에서 실측: **1080x1920 · 540x998 · 720x1600 모두 판이 세로 135~695 · 가로 19~411**
(원본과 같음).

눌리긴 했다. 동작이 `SetHint("편성 변경 화면은 아직 준비 중이에요.")` 라는 자리표시자였고,
