## 기술과 현재 상태

- 요청된 최초 버전은 Unity 6.3 LTS였으나 기존 프로젝트는 이미 **6000.4.5f1**이다.
- 하네스 설치는 현재 버전을 기록했으며 엔진 버전 변경을 승인한 것이 아니다. 기존 작업을 이어갈 때 현재 버전을 사용하고, 6.3 이행은 별도 결정으로 남긴다.
- URP 2D, Grid/Tilemap, SpriteRenderer, uGUI + TextMeshPro, 한국어 폰트, Input System.
- Newtonsoft JSON 공식 Unity 패키지, DOTween, Particle System, Sprite 애니메이션, Unity ObjectPool.
- 세로형 모바일 화면을 기본으로 에디터에서는 키보드/마우스로도 조작한다.
- 기존 `DustZeroUnity/Assets/DustZero/Scripts/Data/GameDatabase.cs`, `TableRows.cs`와 asmdef를 먼저 읽고 확장한다.
- DOTween과 주요 Unity 패키지는 이미 존재한다. 재설치하거나 버전을 임의 변경하지 않는다.
- Unity MCP v10.3.0이 별도로 설치되었다. 루트 `.mcp.json`과 `docs/harness/UNITY-MCP.md`를 참조한다. 실제 연결 대상부터 확인한다.

## 데이터와 구조

엑셀→Python 변환→JSON 흐름과 ID/키/관계를 유지한다. 런타임에 엑셀/Python을 요구하지 않는다.
밸런스 수치를 C#에 중복 하드코딩하지 않는다. 필수 값·참조 ID·형식을 검증한다.
데이터 로딩, 디펜스 시뮬레이션, 생존 시뮬레이션, 성장/보상, 저장, UI/연출을 분리한다.
전투 규칙은 가능한 한 일반 C# 클래스로, MonoBehaviour는 입력·표현·Unity 연결에 사용한다.
ScriptableObject는 자산 연결용으로 사용 가능하나 엑셀과 경쟁하는 수치 원본으로 만들지 않는다.

## 구현할 기능

1. **디펜스:** 맵/배치 조건, 편성, 배치/철수/재배치, 전력, 웨이브/복수 입구,
   지상/공중 이동, 저지/대기열/과열/냉각, 일반 공격/자동 스킬/대상 구분,
   보스/지형, 정지/1·2배속, 승패/별/최초·별 보상, 전투 튜토리얼.
   지상 적은 원본 BFS 거리장의 우회/저지 규칙, 비행 적은 지정 경로를 유지한다.
2. **대청소:** 신규 원본의 무한 생존(구버전은 5분 종료), 리더 선택, 터치/WASD/방향키, 자동 공격,
   생성/보스, 경험치/레벨업 선택, 동료/강화/협동기/편성 효과,
   정지/결과, 일일 보상 횟수/기록. 다수 오브젝트는 풀링한다.
3. **로비:** 홈/스테이지/보유 유닛/편성/뽑기/상세 팝업,
   레벨업/돌파/중복 처리/재화/출석/방치 상한/해금/대표 캐릭터/튜토리얼 재시작.
   테스트 전용 조작은 개발 빌드에서 관리한다.
4. **그림과 UI:** Canvas 그리기 코드를 조사해 원본 모습을 재현한다.
   이미지가 없으면 투명 PNG/스프라이트 시트 추출을 검토한다.
   Safe Area/다양한 비율/한글 폰트/버튼·피격·스킬 연출을 처리한다.
   임시 도형을 최종 자산이라고 보고하지 않는다. 외부 자산 라이선스를 기록한다.
5. **저장:** persistentDataPath JSON, 버전 관리/백업/교체 저장,
   진행도/재화/보유/편성/수령/튜토리얼/시간 복원. PlayerPrefs는 간단한 설정에 한정한다.
   브라우저 저장은 자동 이전으로 가정하지 않는다.
6. **신규 빌드 기능:** 전투 중 강화/멀티탭, 조각 영입/수동 돌파, 7칸 출석, 방 로비,
   7탭·상점·시즌 패스·강제 안내, 일일 시간구간 생존 보상, BGM/효과음/칩튠.
   세부 요구사항은 docs/design/GAME-SPEC.md와 신규 빌드 실제 데이터로 확인한다.

## 순서와 완료 조건

현재 작업 점검→첫 스테이지 완주→디펜스 전체→로비/성장/저장→생존 모드→그래픽/모바일 검증.
씬/프리팹/UI 연결까지 완성한다. Unity 컴파일과 실제 실행, 핵심 규칙 테스트,
저장 복원/보상 중복 방지/길찾기/배치 검증을 수행한다.
`minimal`은 문서를 간소화하는 선택이며 핵심 검증을 생략하는 근거가 아니다.
Unity 실행 파일·씬·테스트가 아직 없으면 미완성으로 보고한다. 빈 테스트 결과는 통과가 아니다.
완료 시 실행 방법, 버전, 실제 검증 결과, 데이터 반영/빌드 방법, 원본과의 차이를 남긴다.
